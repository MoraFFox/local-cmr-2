## Component Patterns

### Function Components with TypeScript
```tsx
interface MyComponentProps {
  data: SomeType;
  onAction: (id: number) => void;
}

const MyComponent: React.FC<MyComponentProps> = ({ data, onAction }) => {
  // ...
};
```

### Memoization
- `React.memo()` used for list item components to prevent re-renders
- `useMemo` for derived data (filtered lists, sorted records)
- `useCallback` for event handlers passed as props
- Memoized date formatter with `Map` cache pattern used in `MaintenanceRecordList`

### Lazy Loading
- All view components in `App.tsx` use `React.lazy(() => import(...))`
- Wrapped in `<Suspense fallback={<LoadingState />}>`

### Controlled Components
- All form inputs are controlled via React state
- `handleFieldChange` pattern: single handler that uses `e.target.name` to determine which field to update

## State Management Patterns

### Prop Drilling (Primary)
State flows from `App.tsx` → View → Components. No Redux or Zustand.

### Custom Hooks for Data Fetching
```ts
const { submissions, isLoading, fetchSubmissions } = useSubmissions(isOnline);
```

### Context for Cross-cutting Concerns
- `ToastProvider` — Toast notifications
- `UndoQueueProvider` — Undo functionality
- `LanguageProvider` — RTL/LTR + translations
- `KeyboardShortcutsHelpProvider` — Shortcut help
- `WizardJumpContext` — Cross-step wizard navigation

## Styling Conventions

### Tailwind CSS
- Utility-first with Tailwind classes
- Dark mode: `dark:` prefix variants
- Custom color tokens in `tailwind.config.js`:
  - `primary` (#B61E24), `hover` (#8F171C)
  - `cream`, `espresso` series for surfaces
  - `leaf`, `ember` series for status indicators
  - CSS custom properties for theme tokens: `var(--bg-body)`, `var(--text-primary)`

### RTL Support
- `ltr:` and `rtl:` prefix variants used for directional styles
- Example: `ltr:justify-end rtl:justify-start`
- `dir` attribute set on root `<div>` from `LanguageContext`

### Component Styling
- Inline Tailwind classes (no CSS modules)
- Shared class strings via `CLASSES` constant in `utils/sharedConstants.ts`
- `input-base` custom utility class defined in `index.css`

## Error Handling

### ErrorBoundary
- Top-level `ErrorBoundary` wraps the entire app in `index.tsx`
- Individual error boundaries used for critical features

### Supabase Errors
- Custom fetch wrapper in `supabaseClient.ts` logs errors and captures response bodies
- 30-second request timeout
- Network errors logged via `logger.ts`

### Form Validation
- `utils/validation.ts` for form validation logic
- `useFormValidation` hook for real-time validation
- `ValidationSummary` component for displaying errors
- `MissingFieldsPanel` for highlighting incomplete data

## i18n Conventions

- Translation keys in `utils/arabicTranslations.ts` and `utils/englishTranslations.ts`
- Accessed via `t()` function from `LanguageContext`
- Pre-commit hook runs `scripts/checkI18n.ts` to find missing translations
- Allowlist: `tests/i18n-allowlist.json`
- Audit tools: `scripts/audit_english_strings.py`, `scripts/lib/i18n-audit.ts`

## Accessibility Patterns

- `aria-*` attributes on interactive elements
- `aria-live` region for dynamic content announcements
- Focus management: mobile menu close → hamburger button return
- Keyboard shortcuts: `Ctrl+Shift+S` for sidebar toggle
- `role`, `aria-label`, `aria-expanded` on interactive components
- Screen reader announcer via `utils/ariaAnnouncer.ts`
